# Протокол sink `http`: транскрибатор → сервер отображения

Версия протокола: **1**. Транскрибатор — клиент: он сам отправляет события сессии
на сервер отображения HTTP POST-запросами. Сервер хранит сессии и показывает их
пользователям; как именно — его дело.

## Транспорт

```
POST <HTTP_SINK_URL>
Content-Type: application/json
Authorization: Bearer <HTTP_SINK_TOKEN>
```

- `HTTP_SINK_URL` и `HTTP_SINK_TOKEN` задаются в `.env` транскрибатора; сервер знает тот же токен.
- Только **HTTPS**: токен идёт в заголовке открытым текстом, его защищает TLS.
  По `http://` транскрибатор шлёт только на `localhost` или с явным `allow_insecure: true`.
- Токен — случайная строка, а не фраза:
  `python -c "import secrets; print(secrets.token_urlsafe(32))"`.
  Сервер сравнивает его за постоянное время (`hmac.compare_digest`).

### Ответы сервера

| Ответ | Что делает транскрибатор |
|---|---|
| `2xx` | пакет доставлен, шлёт следующий |
| `401`, `403` | повторяет **тот же** пакет с паузой (0.5 с → … → 30 с): токен чинится на сервере, события не теряются |
| `408`, `429`, `5xx`, сеть недоступна, таймаут (5 с) | повторяет тот же пакет с паузой |
| прочие `4xx` | считает пакет неисправимым: пишет ошибку в лог и **отбрасывает** его |

Тело ответа не читается (кроме первых 200 символов для лога при ошибке).

## Тело запроса

Один запрос — пакет событий одной сессии (до 50):

```json
{
  "version": 1,
  "session": {
    "id": "6f1c2b9e-0d4a-4c43-9a51-3b1f0e7d2c88",
    "name": "Xy3kP9_qR2mT7vLw1nB4cA",
    "started_at": "2026-10-31T12:34:24.197Z"
  },
  "events": [ ... ]
}
```

- `session.id` — уникален на каждый запуск транскрибатора. По нему сервер различает
  сессии: одну и ту же комнату (`session.name`) могут транскрибировать несколько раз.
- `session.name` — имя комнаты LiveKit (для источника `wav` — `session_name` из конфига).
- `session` есть в **каждом** запросе: сервер создаёт сессию по первому запросу с новым
  `id` и не ждёт события `session_started` (оно могло быть в потерянном пакете).

Все времена — UTC, ISO 8601 с миллисекундами и `Z`.

## События

Общие поля каждого события:

| Поле | Тип | Смысл |
|---|---|---|
| `seq` | int | сквозной номер события в сессии: 1, 2, 3, … (могут быть пропуски, см. ниже) |
| `type` | string | тип события |
| `at` | string | когда транскрибатор создал событие |

### `session_started`

Первое событие сессии, без дополнительных полей.

### `speaker_joined` / `speaker_left`

```json
{"seq": 2, "type": "speaker_joined", "at": "…", "speaker": {"id": "alice", "name": "Alice"}}
```

`speaker.id` — identity участника LiveKit, `speaker.name` — его отображаемое имя
(или identity, если имени нет). Участник может выйти и зайти снова — это новая пара
`speaker_joined`/`speaker_left` с тем же `id`.

### `segment`

Реплика или её промежуточная версия:

```json
{
  "seq": 5, "type": "segment", "at": "2026-10-31T12:34:32.010Z",
  "segment": {
    "segment_id": "alice:1",
    "speaker_id": "alice",
    "speaker_name": "Alice",
    "is_final": true,
    "start": "2026-10-31T12:34:29.860Z",
    "end": "2026-10-31T12:34:31.190Z",
    "text": "Hi, Bob. Can you hear me?"
  }
}
```

- `segment_id` — id фразы, уникален в сессии. Одна фраза может прийти несколько раз:
  сначала `is_final: false` (промежуточные версии, пока человек говорит; только если
  включены interim), в конце один раз `is_final: true`.
- `start` / `end` — когда фраза звучала (по времени созвона, не по времени отправки).
- `text` финала может быть **пустым**: фраза оказалась не речью. Если сервер уже
  показывал её промежуточную версию — реплику нужно убрать.

### `session_ended`

Последнее событие сессии: комната закрыта или транскрибатор остановлен.
Если транскрибатор упал, этого события не будет — сервер может закрывать сессии
по таймауту без событий.

## Гарантии доставки и правила для сервера

- **Порядок.** Транскрибатор держит один запрос в полёте и повторяет неудачный пакет
  раньше всех следующих, поэтому события приходят в порядке `seq`.
- **Дубли.** Если сервер обработал пакет, но ответ не дошёл, пакет придёт повторно.
  Сервер хранит последний обработанный `seq` сессии и пропускает события с `seq` не больше него.
- **Пропуски `seq` — норма.** Промежуточная версия фразы, которую не успели отправить
  до следующей версии той же фразы, не отправляется вовсе.
- **Реплики:** ключ — `segment_id`. Новая версия заменяет старую, финальная — окончательна
  (всё, что придёт по этому `segment_id` после финала, игнорируется). Порядок реплик
  на экране — по `segment.start`.
- **Потери.** При остановке транскрибатор пытается дослать очередь 10 с
  (`shutdown_timeout_s`); всё, что не доставлено к этому моменту, теряется. Пакеты,
  отклонённые прочими `4xx`, теряются сразу.

## Пример: созвон на двоих

```json
{"version": 1, "session": {"id": "6f1c…", "name": "Xy3k…", "started_at": "2026-10-31T12:34:24.197Z"},
 "events": [
  {"seq": 1, "type": "session_started", "at": "2026-10-31T12:34:24.198Z"},
  {"seq": 2, "type": "speaker_joined", "at": "2026-10-31T12:34:24.199Z", "speaker": {"id": "alice", "name": "Alice"}},
  {"seq": 3, "type": "speaker_joined", "at": "2026-10-31T12:34:24.199Z", "speaker": {"id": "bob", "name": "Bob"}}
 ]}

{"version": 1, "session": {…},
 "events": [
  {"seq": 5, "type": "segment", "at": "…", "segment": {"segment_id": "alice:1", "speaker_id": "alice", "speaker_name": "Alice",
   "is_final": false, "start": "2026-10-31T12:34:29.860Z", "end": "2026-10-31T12:34:30.860Z", "text": "Hi, Bob"}}
 ]}

{"version": 1, "session": {…},
 "events": [
  {"seq": 6, "type": "segment", "at": "…", "segment": {"segment_id": "alice:1", …, "is_final": true, "text": "Hi, Bob. Can you hear me?"}},
  {"seq": 7, "type": "segment", "at": "…", "segment": {"segment_id": "bob:1", …, "is_final": true, "text": "Yes, loud and clear."}}
 ]}

{"version": 1, "session": {…},
 "events": [
  {"seq": 31, "type": "speaker_left", "at": "…", "speaker": {"id": "alice", "name": "Alice"}},
  {"seq": 32, "type": "speaker_left", "at": "…", "speaker": {"id": "bob", "name": "Bob"}},
  {"seq": 33, "type": "session_ended", "at": "…"}
 ]}
```

`seq: 4` пропущен: это была промежуточная версия `alice:1`, вытесненная `seq: 5` до отправки.

## Изменения протокола

Несовместимые изменения повышают `version`. Новые поля и новые типы событий могут
появляться без смены версии: сервер должен игнорировать незнакомые поля и типы.

Отладочный сервер, который принимает этот протокол и печатает реплики:
`scripts/http_sink_server.py`.
